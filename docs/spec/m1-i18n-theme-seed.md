## Behavior

### Multi-language (T-129)

- Two languages: Vietnamese (VI) and English (EN).
- All visible text comes from message catalogs. There is no hard-coded text in code (Plan T-129).
- Dates, numbers and money follow the language (same helper as T-05):
  - Vietnamese: decimal comma, `d/m/yyyy`, amount suffixes "triệu" and "tỷ" for compact money.
  - English: decimal point, `Mon d, yyyy`, "M ₫" and "B ₫" for compact money.
  (Prototype `dec()`, `fmtDate()`, `money()`; the compact style is still open in Q-FND-4.)
- Switching language re-renders the page without a reload and updates the document `lang` attribute (Prototype `render()`).
- Names in data (shop names, product names, notes) are not translated; only app text is. Seed notes with both languages are catalog data.

### Light and dark themes (T-130)

- By default the theme follows the system setting. A manual toggle overrides it and is remembered (Prototype `ACT.theme`).
- Every color is a token with a light and a dark value, including the chart series colors the Prototype names `--c1` to `--c5`. Every chart must stay readable in both themes. No chart ships in M1, so M1 delivers the tokens and a readability check that later chart tickets reuse.
- The login screen and the pending screen also follow the theme and language (Prototype `put()` shows the toggles there).

### Sample data and test accounts (T-134)

- A sample dataset that matches the Prototype, for demos and tests (Brief 10: "realistic, consistent sample data").
- Prototype reference data:
  - "Today" is 2026-11-23, the data starts 2026-08-24 (about 90 days), generated by a seeded random generator so results repeat.
  - Business B1 "Mộc Mạc" (active, has data) with three shops: Mộc Mạc Official and Mộc Mạc Gốm on TikTok Shop, Mộc Mạc Shopee on Shopee.
  - Business B2 "Sắc Việt Decor" (active, no data), to test the empty workspace.
  - Accounts: System Admin; Admin Nguyễn Thu Lan (B1, all modules); Users Trần Minh (Overview, Sales, Inventory, Supplier), Lê Hà (Overview, Sales, Marketing, Finance), Đặng Sơn (Sales, Reports); Admin Võ Khang (B2); and Phạm Quỳnh, a Pending registration.
- The seed must be repeatable (running it twice does not duplicate data) and must be able to grow when later milestones add tables. See Q-SEED-2.

## Edge cases

- A translation key is missing for the active language: show the English text, and report the missing key in development and in tests. (Proposed)
- Text length differs between languages: no clipped or overflowing labels in the shell. (Proposed)
- A browser blocks local storage: the app still works, with the system theme and the default language. (The Prototype wraps storage access in try/catch.)
- A user changes language or theme on the login screen, then signs in: the choice is kept. (Proposed)
- Seed run against a non-empty database or against production: refuses to run. (Proposed; Q-SEED-3)

## Acceptance criteria

- [ ] The whole app can be used in Vietnamese and in English, with no hard-coded text, and the language can be switched at any time.
- [ ] Dates, numbers and money follow the language.
- [ ] The theme follows the system by default, has a manual toggle, and the choice is remembered.
- [ ] Every color token has a light and a dark value and passes a readability check in both themes.
- [ ] The seed creates the sample accounts, Businesses and shops listed above, with the module grants shown, and can be re-run safely.
- [ ] Tests and demos can sign in with each sample account (Q-SEED-3).

## Out of scope for M1

- Responsive layout verification and accessibility audit (M8; build responsively from M1, per the Plan).
- Seeding the module data (orders, products, costs) before the tables exist (see Q-SEED-2).
