# T-01: Design the extensible data model

## User story

As the platform, I need an extensible data model so that every later module can be built without redesigning the data.

## Acceptance criteria

- [ ] A Business holds many shops; an account can later belong to several Businesses
- [ ] Permissions stored per user, module and level
- [ ] Taxpayer profile and platform connections are their own records
- [ ] Seller type is a list (Individual, Household business) that can gain Company later
- [ ] ER diagram approved

## Dependencies

None.

## Size

L (5 effort points). Priority P0.
